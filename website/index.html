The leak nobody budgets for

AI coding assistants log, cache, and sometimes retain what you paste. Client tickets, payroll runs, API keys, .env files — the moment they hit the chat, they're on someone else's servers, subject to someone else's retention policy.

Redaction tools that just delete the data kill the work: the model needs the shape of your data to help you. ClaimCheck keeps the shape and drops the exposure.

Mask → work → restore

  1. Mask. Sensitive values become stable placeholders — [FEIN_1], [SSN_2], [PERSON_1] — before the request leaves your machine. The mapping stays in a local vault file.
  2. Work. The model reasons over placeholders. Same value, same placeholder, every time — references and context stay consistent across the whole session.
  3. Restore. The response crosses back through the vault and placeholders become real values again. Locally.

Three ways to run it: MCP tools your agent calls directly (Cline, Claude Code, OpenClaw), a CLI for files and pipes, or a scrubbing proxy that sits between any OpenAI-compatible client and its provider and sanitizes everything on the wire — with a fail-closed posture: if scrubbing fails, the request is held, not forwarded.

Cline integration

Cline users get ClaimCheck in one of two ways — both local, both reversible:

  • MCP tools. Add the ClaimCheck MCP server to Cline's MCP settings; the model then reads files through it and receives scrubbed content with stable placeholders instead of raw identities. The exact mcpServers JSON is in the install guide.
  • Scrubbing proxy. Install with -WithProxy and point Cline's model provider Base URL at http://127.0.0.1:8766/api/coding/paas/v4 — every request to the model is scrubbed on the wire, and every response is restored before the editor sees it.

What it catches

26 recognizer types, deterministic, validated, no cloud calls: SSNs · FEINs/EINs · emails · account numbers · API keys (OpenAI, AWS, Slack, GitHub) · JWTs · passwords and labeled secrets (JSON/YAML/.env aware) · PEM private keys · encoded base64/hex dumps · card numbers + CVV + expiry · IBAN · bank routing · phone numbers · IP addresses · street addresses · dates of birth · passports · driver's licenses · medical licenses · insurance member IDs · IMEI · URL credentials.

An opt-in NER tier adds free-text names, organizations and locations via a local ONNX model — cached once, no uploads, no API calls — with a type whitelist (SANITIZE_NER_TYPES) and global or per-type confidence floors. Domain-specific values (customer IDs, member codes) drop in via a .sanitize-patterns.json file — same ticket contract, your regexes.

Why trust it

  • No account. No API key. No telemetry. Nothing phones home — ever.
  • Fail-closed. A scrub failure holds the request instead of forwarding raw text.
  • Open source. MIT-0. The whole engine is on GitHub — audit it, fork it, self-host it.
  • Stacks, doesn't fight. Repo scanning (Semgrep), tool-lane firewalls (Sunglasses), model-hop scrubbing (ClaimCheck) are different enforcement points on the same wire — run them together. ClaimCheck is the layer that keeps the session working instead of stopping it.
  • Honest limits. ClaimCheck protects the model-provider hop. Whatever reached a chat surface before the sanitizer ran was already seen — the docs state this plainly instead of hiding it.

New in v0.9

  • Realistic mode (SANITIZE_FAKE_DATA=1). Instead of opaque tickets, the model sees deterministic, per-type fakes — 9XX-00-XXXX SSNs, Luhn-valid cards, @claimcheck.invalid addresses — and restore swaps fakes back to real values. Same round trip, zero formatting drift.
  • Dates off by default (v0.9.2). Dates are operational context — ticketing them broke "which deadline is earlier?" reasoning. Opt back in with SANITIZE_DATES=1; old vaults still restore.
  • Vault tools. vault-list inspects every vault on the machine (full or --summary), restore --vault pins exactly one vault, restore --bare strips ticket decorations — and the default sweep now warns on same-ticket/different-value conflicts instead of guessing.
  • Audit trail (SANITIZE_PROXY_LOG=1). Proxy logs post-scrub request bodies as JSON lines — tickets only, never raw values. Compliance sees the shape of the traffic; the vault never joins the log.
  • Hardened edges. Encrypted vaults at rest (DPAPI on Windows, portable AES-GCM via SANITIZE_VAULT_PASSWORD), path allowlists (SANITIZE_ROOTS), fail-closed HOME resolution, and an optional Presidio analyzer as a fourth, tier-separated detector.
  • One-line installs everywhere. Windows PowerShell, Linux x64/ARM64 per-user, and the claimcheck-upgrade appliance path for Raspberry Pi / systemd boxes.

Why the name

The tool ran nameless through its first build night. The first candidate was Cloakroom — rejected on arrival, because a Claude Code tool with the identical concept had shipped under that exact name the very same week. Great minds.

The collision search landed on ClaimCheck, and it fit better anyway. A claim check is the stub you get when you hand your valuables over at the coat check: you work the room with a numbered ticket and redeem it for the real thing on the way out. That's the whole product — your AI assistant works the session with claim tickets like [FEIN_1], and the local vault redeems them at the door.

Software has a second meaning for the phrase, and it's the same idea: Claim Check is a named pattern in Enterprise Integration Patterns — store the payload in an external store, pass only a reference through the channel, redeem it at the destination. This tool is that pattern, applied to LLM traffic.
